## 五次修复（释放技能闪退 → 换安全方案）

### 闪退原因
上版 3 个 CodeCave 里 ccMagicFireArrowWhitelist @ 0x955D0E 强制跳 0x956372 多目标块：
- 该块代码依赖白名单技能(2201005等)路径特有的初始化状态(v192/v193等)
- 火焰箭跳进去后数据状态不兼容 → 访问非法内存 → 崩溃

### 更安全的方案（单目标路径扩展，不跳块）
TryDoingMagicAttack 单目标路径本身有官方多目标扩展开关：
```
0x955ED4: cmp [ebp-0x14], 0x21E3CE   ; v233 == 2221006?
0x955EDB: jz 0x955EEA                 ; → sub_67886D 扩展
0x955EDD: cmp [ebp-0x14], 0x1524D7B  ; v233 == 22171003?
0x955EE4: jnz 0x95612F
0x955EEA: sub_67886D(pool, &v187, v234, v195, v207, v218, 150)  ; 以锁定目标为中心搜周围怪
```
火焰箭不在两技能中 → 不扩展 → 只打1只。v207(=[ebp-0x90]) = maxTarget = 1。

**ccMagicFireArrowExpand @ 0x955ED4（覆盖8字节）**：
- 火焰箭: v207=3 + jmp 0x955EEA 进入 sub_67886D 扩展
- 其他: 恢复原 cmp/jz 判断
sub_67886D 是官方通用函数(2221006/22171003 也在用) → 安全不会崩

### 关键地址
- dwMagicExpandCheck=0x955ED4, Rtn=0x955EDD, Call=0x955EEA
- sub_67886D 参数: this=CMobPool, &v187, v234(锁定目标), v195(数组), v207([ebp-0x90]压栈), v218(方向), 150(半径)

### 经验
- MSVC 内联汇编条件跳转(jz/jne)不能直接跳绝对地址(constexpr)，需本地label+无条件jmp
- 强制跳入官方"多目标块"风险高(依赖白名单技能特有状态)，优先在单目标路径做扩展

## 八次修复（"还是不攻击" → 矩形坐标系错误！）

### 根本原因
上一版矩形扩大 CodeCave 在 `call dword_BF0454` **之后**设置 v219 = -1000..1000（相对值）：
- dword_BF0454(&v219, x, y) 的作用是**把相对矩形平移到玩家位置**（变绝对坐标）
- 怪物坐标是**绝对坐标**（世界坐标），相对矩形 -1000..1000 覆盖不到 → FindHitMobInRect 返回 0 → 不攻击

### 修复（时序修正）
矩形设置移到 `call dword_BF0454` **之前**：
```
cmp [ebp-0x14], 2101004
jne normal
mov [ebp-0x58], -1000    ; v219.left (相对)
mov [ebp-0x54], -400     ; v219.top
mov [ebp-0x50], 1000     ; v219.right
mov [ebp-0x4C], 400      ; v219.bottom
normal:
mov eax, 0x00BF0454
call dword ptr [eax]     ; 平移成绝对矩形 = 玩家±1000/±400 ✓
jmp 0x956573
```
dword_BF0454 把相对矩形平移成**以玩家为中心的绝对矩形** → FindHitMobInRect 用绝对坐标搜索 → 能搜到远处怪

### 机器码验证
81 7d ec 0c 0f 20 00 (cmp 2101004) → c7 45 a8 18 fc ff ff (-1000) → ... → b8 54 04 bf 00 + ff 10 (call [eax]) ✓ 顺序正确

### 编译
成功 out/Release/ijl15.dll (22:36, 303KB)

### 教训
dword_BF0454 = 矩形平移函数：输入相对矩形，输出绝对矩形（玩家中心）。要在 call 前设相对值，call 后是绝对坐标，不能覆盖成相对值！
